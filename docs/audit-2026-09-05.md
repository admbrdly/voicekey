# Architecture audit — 2026-09-05

At the audited baseline, the project had a usable foundation but needed
repairs before persistent mode: explicit ownership, delivery evidence,
deadlines and failure recovery. The recognition adapters, target boundary,
separate workers, configuration validation and recovery utilities were worth
keeping. A rewrite or a general plugin framework was not justified.

**Repair status (2026-09-05).** The findings below describe the audited
baseline. The accepted hold-to-talk repairs have since been implemented:
explicit utterance ownership, bounded admission and execution, journal-before-
delivery, conservative field identity, revision-checked replacement, typed
outcomes, expiring/idempotent Emacs operations, capture/shutdown cleanup, and
polish preservation with a configurable eight-word minimum. The persistent
architecture has been rewritten around those contracts. The repair suite
passed 189 Python tests, including a batch run of 15 editor tests and a private
Emacs server test. Continuous listening remains unimplemented.

**Preview follow-up (2026-09-05).** The user chose shared native Wayland
previews, including in Emacs, as the default for persistent mode. Inline
previews have been restored while keeping acknowledged, expiring buffer
insertion. Emacs overlays and per-utterance anchors are deferred until a
demonstrated need; they are not prerequisites for the first persistent mode.
The restored preview path passes the expanded 199-test Python suite, including
the same editor checks and new preview binding, ordering and cancellation cases.

The findings and original work order below describe that audit. The current
next steps are maintained in the
[architecture handoff](persistent-mode-architecture.md#handoff-for-the-next-session).

The remaining limits are explicit: generic IME/wtype submission is not an
application acknowledgement; an untracked Emacs pin names the buffer when its
timely request executes; polish checks cannot prove meaning preservation; and
native calls that cannot be cancelled retain bounded execution slots. Real
compositor behavior and model-quality/latency measurements remain integration
work. These are documented boundaries, not claims that the unit tests prove
perfect delivery or perfect transcription.

## Scope and evidence

Reviewed all handwritten Python modules, relevant generated protocol
documentation, the tests, installation/service configuration, both persistent
mode plans, recent Git history and the local service journal from September 2
onward. Baseline: `e59858f`, including the existing uncommitted diagnostic
changes in `README.md`, `voicekey/polish.py`, `voicekey/__main__.py` and
`tests/test_polish.py`. Those changes were left intact.

All **199 existing tests passed**, in 7.352 seconds. The initial sandbox run
could not create sockets for 15 tests; rerunning with localhost sockets
permitted resolved those environment failures. Test output was saved at
`/tmp/voicekey-audit-tests.log`.

Additional isolated checks exercised actual Python state/target code with
fake protocol endpoints, a temporary HTTP server, a synthetic recorder
process, and the actual insertion forms in a separate batch Emacs with Evil.
No live desktop delivery, microphone capture, service restart or agent
dispatch was performed. These establish executable failure paths, not their
frequency in normal use. Real compositor/application interactions and model
accuracy still require integration measurements.

The journal corroborates that focus loss and IME takeover matter in practice:
four field-change fallbacks on September 4, and several IME takeover warnings
on September 5. It does not establish that every failure identified here has
already happened to a real dictation.

## Findings in the existing code

### 1. High: reactivation is not a persistent field identity

**Location:** [target.py](../voicekey/target.py), `ImeTarget._commit` and
`_reactivated` (lines 245–278); `bind` (346–368).

After the original activation refuses a commit, any new activation in the
same window is accepted. Dictate in field A, switch to field B within that
window, and the final transcript can land in B. The isolated check returned
`landed=True` with generation 2 for a target originally bound to generation 1.
The README's promise of delivery only to the original field is therefore too
strong. The plan explicitly allows “any field” on reactivation, which is a
different policy and needs to be acknowledged as such.

Binding also reads the IME generation, compositor window and Emacs buffer
through separate channels at different times. In particular, `PendingPin`
captures the selected buffer when its Lisp runs, not when the Python request
was created. Once established, the pin is useful; acquisition is not an
atomic snapshot of key-down.

**Required direction:** distinguish a stable editor buffer from an IME
activation and from a window-only target. Use those capabilities to state
honest guarantees. Without evidence of the original destination, preserve
pending text and require a deliberate rebind rather than silently treating
window identity as field identity. Validate Emacs binding in the editor
integration spike before relying on it for a long session.

### 2. High: reconciliation can duplicate text or delete unrelated text

**Location:** [ime.py](../voicekey/ime.py), `left_showing`, `_on_done`,
`_apply` (162–165, 255–263, 275–297);
[target.py](../voicekey/target.py), `_commit` (261–271).

`_left_showing` is a single global string, overwritten by every deactivation.
The reproduction showed that visiting an unrelated field and leaving it
replaced the original provisional history with `""`. On return, the code can
then insert the final text beside provisional text the original field kept.
Likewise, absence from a limited surrounding-text report does not establish
absence from the document.

Replacement has a separate race: the delivery thread checks the surrounding
text, then queues a deletion by byte count. If the cursor moves within the
same activation before that request executes, `_apply` uses the latest serial
and deletes at the new cursor. The reproduction changed the surrounding
report after the check; the replacement still issued `delete(7, 0)`.

**Required direction:** retain shown text per binding/render revision, and
carry the checked activation, surrounding-text revision and expected text
into the operation. Validate them together on the IME thread before issuing
a replacement. Unknown or incomplete evidence must remain unknown. A ledger
alone cannot infer what another application retained.

### 3. High: delivery outcomes conflate submission, refusal and uncertainty

**Location:** [ime.py](../voicekey/ime.py), `_call` and `_apply` (183–221,
275–297); [target.py](../voicekey/target.py), `Landing`, `EmacsTarget.land`
and `WtypeTarget.land` (59–72, 308–334).

IME success currently means that requests were marshalled and `flush()` was
called. It does not acknowledge insertion into an application. The installed
PyWayland implementation returns `-1` on flush failure, including temporary
backpressure; voicekey ignores that result. A fake flush returning `-1`
still produced `True` from `_apply`.

Conversely, a started `_call` whose function raises returns false because
exceptions do not populate its result. That is not necessarily evidence that
no requests were sent. A `wtype` timeout can follow partial typing, but every
typing exception is classified as safe to copy. An Emacs error after a
mutation, for example from an editing hook, is also treated as a refusal.
Timeouts already have an uncertainty path; other partial failures need it too.

**Required direction:** track operations by ID and distinguish refused before
submission, submitted, confirmed where supported, and unknown/partial.
Preserve uncertain text without inviting a blind repeat. Handle flush errors
and backpressure. Emacs can acknowledge and deduplicate operation IDs; the
generic protocol cannot provide the same application-level guarantee.
Its local protocol documentation is in
[_input_method_v2.py](../voicekey/_input_method_v2.py), `commit` (641–665).

### 4. High: time limits and queue bounds are incomplete

**Location:** [daemon.py](../voicekey/daemon.py), queue construction,
`_queue`, `_polish_worker`, `_budget` (311–316, 501–519, 629–655, 701–704);
[polish.py](../voicekey/polish.py), `OpenAIChat.chat`, `Polisher.polish`
(138–169, 257–279); [target.py](../voicekey/target.py), `Window.await_`.

Only the transcription and agent queues have size limits. The polish and
delivery queues retain entire `Job`s, including audio, without a cap. Audio
alone costs about 64 KB per recorded second. Continuous input can outpace a
slow downstream stage indefinitely unless the mode has an explicit overload
policy. A blocked native transcription call is also currently unbounded.

The polish timeout is a socket-operation timeout, not a total deadline.
A temporary server sending pieces less than 0.15 seconds apart made
`polish(..., wait=0.15)` return an accepted result after **0.358 seconds**.
This agrees with the [Python timeout documentation](https://docs.python.org/3.12/library/urllib.request.html#urllib.request.urlopen).
Queued jobs also get their polish wait when the polish worker starts them,
rather than an absolute deadline established at transcription completion.

`finished_at` is sampled after recorder shutdown and decoder finalization;
those delays are excluded from transcript age. `_budget` then grants at
least one second even when less remains. Focus queries, polling and target
operations have their own waits rather than consuming one shared deadline;
the focus poll accepts a successful result before checking expiry.

**Required direction:** absolute monotonic deadlines, established at the
relevant event and carried through every stage. An independent coordinator
must adopt raw text when polish expires; the blocked polish worker cannot
be responsible for its own timeout. Bound work by count and audio bytes or
seconds; release audio after its last consumer. On overload, preserve work
and pause capture. Use a bounded worker/process strategy for operations that
cannot be cancelled; do not spawn an unlimited replacement thread per timeout.

### 5. High: capture and shutdown lack a complete lifecycle

**Location:** [recorder.py](../voicekey/recorder.py), `_pump`, `stop`
(65–99); [daemon.py](../voicekey/daemon.py), `Session.finish`, `feed`,
`close`, `_on_tick` (216–257, 366–369, 561–568);
[__main__.py](../voicekey/__main__.py), `main` (45–61).

`Recorder.stop()` kills the child only if the reader thread remains alive.
A child that closes stdout but stays alive leaves that thread finished and
`stop()` blocked reading stderr. This was reproduced with a synthetic child
that ignored SIGINT; the audit explicitly killed it to clean up. Stderr is
also undrained during capture, so enough diagnostic output can stall a child.

`Session.finish()` runs native `stream.finish()` synchronously on the key
listener thread after the bounded join. That call itself has no timeout.
The capture callback's overflow path acquires a lock also held while posting
previews, so its “never blocks” contract is not strict either. A spontaneous
recorder exit is not handled by `_on_tick`; normal mode notices at release or
the recording limit.

`Daemon.close()` stops only the polish server. It does not stop capture,
clear/close the IME, close the gate, or save and drain pending work. SIGTERM
has no handler. Systemd terminates the process group through its service
lifecycle, but that is not a transcript-preserving shutdown protocol.

**Required direction:** an explicit owner for each process/thread, bounded
stop and escalation, capture failure events, nonblocking enqueue on the
audio path, and final decoding off the listener. On stop, close capture
first, drain within a deadline, preserve the rest, then close resources.
Test this through the controller rather than relying on process exit.

### 6. High: several failure paths discard the only recoverable recording

**Location:** [daemon.py](../voicekey/daemon.py), `_queue`,
`_transcription_worker`, `_process`, `_keep`, `_copy_instead`
(524–529, 572–627, 706–715); [recovery.py](../voicekey/recovery.py).

A full transcription queue discards the newest recording without saving it.
A transcription exception clears the preview and reports an error, but does
not recover audio or the available live transcript. Even with
`recordings_dir` enabled, `_keep` runs only after successful transcription
(and after polish if enabled). Recording failure/disconnection paths also
discard captured material. A hung transcriber therefore leaves no durable
record of its pending audio.

`last-recovery.txt` is correctly atomic and private, but successive failures
overwrite each other. That is a last-result convenience, not preservation of
a backlog. Recovery is written after the clipboard attempt, leaving another
window in which a crash loses the transcript.

**Required direction:** preserve accepted utterances before fallible stages,
and known text before delivery. Keep an append-only per-session record with
unique IDs, with `last-recovery.txt` as a convenience pointer/copy. Specify
audio-spool policy separately from text journaling and distinguish process
crash recovery from power-loss durability. Disk failure must trigger an
explicit degraded state or pause, rather than silently voiding preservation.

### 7. High for paper dictation: the polish guard does not protect meaning

**Location:** [polish.py](../voicekey/polish.py), `judge` (226–246);
[daemon.py](../voicekey/daemon.py), empty-result handling (648–653).

The empty-result test measures word count, not whether words are fillers.
Both `"I disagree." → ""` and `"Do not publish." → ""` pass, causing the
dictation to be dropped. The guard also accepts
`"The conclusion does not follow." → "The conclusion does follow."`.
It limits growth and novel vocabulary but has no general protection against
deletion, reversal, changed numbers or changed names. These are deterministic
judge checks; they do not claim the deployed model produced these examples.

**Required direction:** reject empty output for content-bearing input; the
safest initial policy is to reject all empty output. Treat the other checks
as heuristics, not semantic guarantees. Keep raw text independently, add
content-loss checks where useful, and evaluate actual paper dictation with
negation, qualifications, names and formulae. Keep model choice separate from
pipeline correctness. More APIs or models need not precede persistent mode.

### 8. Medium: the gate can unlock during release finalization

**Location:** [daemon.py](../voicekey/daemon.py), `_finish`, `_queue`,
`_settle_gate`, `_landing` (494–523, 547–554);
[gate.py](../voicekey/gate.py), `settle`.

`_finish` clears `self.session` before stopping the recorder and enqueueing
its job. If the previous delivery finishes during that interval, its worker
sees no session and no unfinished queue item and releases the gate. The
reproduction observed `gate.held == False` while the current recording was
still being finalized; enqueueing reacquired it afterwards.

There is also no periodic acquisition retry if another process holds the
shared lock at recording start. The next transition can be release, so most
of that recording can be ungated.

**Required direction:** a token owned by the utterance from first capture
through terminal outcome, transferred without a gap. Derive gate state from
those tokens, not independent queue counters. Retry contested acquisition
without blocking capture. The advisory gate remains coordination, not proof
of target identity.

### 9. Medium: spacing is sampled at the wrong position in Evil normal state

**Location:** [emacs.py](../voicekey/emacs.py), `PIN` and `INSERT`
(49–52, 81); [daemon.py](../voicekey/daemon.py), `Spacing`.

PIN reads `char-before(point)`, while normal-state delivery uses `evil-append`
and inserts after the character at point. In a batch Emacs with `a b` and
point on `b`, PIN returned a space. The spacing rule consequently supplies no
separator, and the real insertion form produced `a bnext`.

More generally, spacing cached at key-down can become stale when the user
types or moves point. `Spacing.user_typed()` clears continuation state but
does not invalidate a known `Job.before` report.

**Required direction:** resolve spacing at the actual insertion anchor and
gesture, preferably in the target's transaction. Session-internal joining
can remain a pure text rule. Exercise the Lisp, not just substring-match the
generated forms.

## What should stay

The source is readable and mostly organized by responsibility. The target
extraction removed application branches from delivery orchestration. Speech
backends have a small useful contract; polish already separates transport,
prompt format and judgement. Strict config parsing catches misspellings and
bad values. Downloads use staging and checksums. Recovery's atomic rename
and permissions are sound for its stated single-file role. Agent delivery
has its own queue and uses stdin for prompt transfer, with strict SSH options.

The existing worker tests do verify worthwhile behavior: slow delivery does
not prevent another transcription, expired queued IME calls are cancelled,
and late live-decoder output is suppressed after cancellation. Keep those
tests and adapters while strengthening their boundaries.

`daemon.py` currently owns mode control, live decoding, spacing, job state,
queues, delivery budgets, recovery and gate accounting. That concentration,
and the duplicated lifecycle represented by `Session`, `Job`, counters and
queue internals, is the main structural problem. Splitting files alone would
not solve it. A single authoritative utterance lifecycle would.

## Corrections needed in the persistent-mode design

1. **Separate preview state from delivery commands.** The proposed
   `render() -> (head, tail)` mixes a repeatable view with a side effect.
   A final utterance must remain visible while its commit waits. Reserve an
   utterance as `delivering` before posting its operation; record an attempt
   ID and an outcome. Coalesce preview snapshots only. Never coalesce,
   discard or regenerate a commit as if it were a cosmetic refresh.

2. **Keep the ledger pure and its lock short.** The plan currently writes
   the session file and posts target updates while holding the ledger lock.
   That couples capture/cutting to disk and target stalls. Let transitions
   produce ordered events/actions; a journal writer and target dispatcher
   perform I/O outside the lock. Require the relevant journal acknowledgement
   before delivery, with bounded buffering and an explicit disk-failure path.

3. **Make stop and restart invalidate old work.** Each event/result needs
   a session ID, utterance ID and revision; delivery needs an attempt ID.
   A late polish result, an Emacs form that executes after timeout, or a
   queued preview must not affect a drained or newer session. `saved` is a
   persistence fact, not proof that an outstanding insertion cannot still
   occur. Carry that uncertainty separately, and add editor-side expiry and
   deduplication where possible.

4. **Define segmentation as sample ownership, including lookback.** A cut
   in the middle of a pause is discovered after that sample has passed.
   The decoder may already have consumed later frames. Specify retained
   history, sample-indexed boundaries and how the new decoder receives the
   suffix. “Finish the old stream and start another” is insufficient for
   retrospective cuts. The guarantee that every sample belongs to an
   utterance also conflicts with discarding long silence; explicitly account
   for discarded silence. Hard maximum cuts cannot promise to fall in silence.

5. **Prove the Emacs anchor contract early.** A marker planted by an
   asynchronous request records point when Emacs handles it, not necessarily
   point at the cut. Verify the last-user-command approach and choose a
   precise anchoring rule, including movement while a pin is pending. Also
   specify marker insertion types and same-position commit order; test normal,
   visual, narrowed, killed and read-only buffers. Exact later replacement
   requires validating that the region still contains the committed text.

6. **Resolve focus and microphone policy in the specification.** The promise
   that the microphone never turns itself on conflicts with automatic resume
   after an absence pause. Distinguish armed, capturing, paused and off; say
   which states permit automatic resume. Make focus handling capability-based:
   a pinned Emacs buffer does not become unavailable when a PDF gains focus.
   Generic IME reactivation needs the conservative treatment in findings 1–2.
   Unsupported voice commands such as `scratch that` need an explicit policy
   on targets that cannot replace committed text.

7. **Bound the whole session, not just each utterance.** Specify pending audio
   seconds/bytes, pending text, request queues, retained ledger history and
   journal retention. Define overload, inactivity, lost keyboard, dead target,
   failed capture and stop-during-drain transitions. Persist an utterance
   before releasing its gate token, including failure paths. No-speech silence
   should release the gate once earlier utterances are terminal.

The useful component boundaries are therefore:

| Component | Owns |
|---|---|
| Controller | Keys, mode transitions, capture lifecycle and stopping |
| Capture/segmenter | Sample indices, bounded audio and cut events |
| Ledger | Utterance state, revisions, ordering and preview snapshots |
| Pipeline coordinator | Worker results, deadlines, overload and delivery reservations |
| Journal | Durable text/audio policy and recovery records |
| Targets | Destination capabilities, insertion anchors and operation evidence |

These are responsibility boundaries, not a demand for six new frameworks or
one thread per component. Existing plain classes and queues are sufficient
for most of them. A few narrow typed contracts would help: immutable work
items/results, a target capability record, and an outcome enum instead of
independent booleans that permit contradictory states.

## Recommended order before implementing the mode

1. **Repair demonstrable hold-to-talk defects.** Add regression cases for
   reactivation, stale replacement, polish deletion, release/gate interleaving,
   recorder stop, flush failures and Evil spacing. Preserve the current
   behavior where sound; correcting unsafe behavior should not be described
   as a behavior-preserving refactor.
2. **Revise the architecture contract and run the Emacs spike.** Settle
   target identity, anchoring, stop/expiry semantics and the honest scope of
   delivery/preservation guarantees before designing ledger operations.
3. **Introduce the utterance lifecycle and bounded coordination using
   hold-to-talk first.** Include journal policy, absolute deadlines, explicit
   delivery attempts, gate ownership and shutdown. Keep this separate from
   continuous audio so failures remain easy to isolate.
4. **Implement continuous capture and segmentation with deterministic replay.**
   Assert sample coverage, suffix replay, output order and bounded backlog
   under slow/failing workers. Use a fake target; the current desktop replay
   command is not a safe unattended integration runner.
5. **Add persistent mode and the editor integration.** Verify long sessions,
   focus loss, typing during previews, pause/resume and stopping with queued
   work. Then measure actual CPU, memory, latency and transcript quality on
   both machines. Additional polish providers and paragraph editing can wait.

The highest-value additions to testing are controlled concurrency schedules
(events/barriers rather than sleeps), a protocol fake that models application
state and rejection rather than merely recording calls, and batch Emacs/ERT
tests of the actual forms. Move target-specific cases out of the 1,206-line
`test_daemon.py` as the interfaces stabilize, and automate the suite in CI.
Neither broad test-count growth nor a new speech model substitutes for those
boundary tests.
